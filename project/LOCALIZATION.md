# Полный перевод и производительность · 2.1

Интерфейс, 120 рецептов, 100 продуктов, названия и количества ингредиентов, шаги приготовления, 6 встроенных уроков и подписи 8 внешних видео доступны на русском, английском и польском. Внешние сайты, звуковая дорожка видео и пользовательские данные (имя, email, произвольные названия) остаются в оригинале.

## Почему локальные переводы

Каталог фиксированный, поэтому переводы поставляются внутри APK: не требуются API-ключи, интернет, отправка данных или загрузка языковых моделей. На английский и польский подготовлено по 302 строки контента дополнительно к переводам интерфейса. Переводы можно редактировать и проверять до выпуска приложения. Внешний Translation API не подключён намеренно.

## Как обновлять

- `project/content_titles.txt`: стабильный ID продукта/рецепта, английское и польское название, разделитель `|`.
- `project/content_steps.json`: исходный русский шаг и оба перевода. Перевод привязан к тексту, а не к позиции рецепта.
- `project/content_lessons.json`: переводы уроков и подписей видео по ID.
- `python project/build_content_translations.py`: собирает `app/src/main/assets/translations/en.json` и `pl.json`.
- `python project/check_translations.py`: проверяет ресурсы интерфейса.
- `gradlew.bat testDebugUnitTest`: проверяет полноту перевода контента, числовые значения и переключение подписей старых записей.

Для новых рецептов добавляйте новые стабильные ID и переводы. Обновление самого исходного каталога в уже установленной базе требует отдельной миграции наполнения; обновление переводов в APK её не требует.

## Сохранение данных

SQLite продолжает хранить исходные описания и числовые значения. ContentLocalizer создаёт переведённую копию только текстовых полей. Смена языка не меняет ID, граммы, БЖУ, избранное, планы и прогресс. Названия известных блюд в ранее сохранённом дневнике отображаются на выбранном языке через словарь исходных и переведённых названий; произвольные названия остаются как введены.

## Сделанные оптимизации

- Словари загружаются в фоновом потоке один раз и повторно используются.
- Исходные JSON-записи каталога читаются из SQLite один раз за жизнь репозитория; смена языка перестраивает только отображаемые модели.
- Поиск рецепта по ID использует Map вместо перебора всего каталога.
- Поисковый текст, теги и аллергены подготавливаются при создании модели. При вводе запроса они не собираются заново для каждой карточки.
- Поиск понимает польские буквы и ввод без диакритики, например `losos` находит `Łosoś`. Сортировка соответствует выбранному языку.
- Ожидающие задачи поиска отменяются при следующем вводе; задержка 180 мс объединяет быстрые нажатия. RecyclerView и DiffUtil переиспользуют карточки.
- После восстановления процесса Android экран рецепта сам подготавливает каталог, не полагаясь на уже открытую MainActivity.

## Анимация запуска

Первый экран плавно появляется и поднимается на 8 dp за 220 мс, один раз за запуск процесса. Искусственная задержка заставки отсутствует, кнопки не блокируются. При отключённых системных анимациях эффект пропускается. Реализация — `StartupMotion.java`, стандартные Android ViewPropertyAnimator и ValueAnimator; дополнительные библиотеки не нужны.

Это конкретные оптимизации загрузки и поиска. Полный профиль производительности на разных физических устройствах не выполнялся; универсальное отсутствие задержек не заявляется.
