# Проект NutriFit

## Идея

NutriFit — Android-приложение на Java для учёта питания, приблизительного расчёта дневной нормы калорий и наблюдения за изменением веса. Пользователь ведёт дневник еды, видит потреблённые калории и БЖУ, а также получает предложения блюд с учётом оставшихся калорий, вкусов и выбранных пищевых ограничений.

Цель проекта — показать полный цикл разработки мобильного приложения: интерфейс, ввод и проверку данных, локальную базу, вычисления, персонализацию, тестирование и демонстрацию.

Среда разработки: Android Studio. Язык приложения: Java. Интерфейс: Android Views + XML. Хранение: SQLite и SharedPreferences. Совместная работа: GitHub. Приложение работает офлайн после установки.

## Пользовательский сценарий

Первый запуск → создание профиля → расчёт дневной нормы → главный экран → добавление еды → пересчёт остатка → предложения блюд → запись веса → просмотр прогресса.

В анкете: имя, возраст, рост, текущий и желаемый вес, параметр пола для расчётной формулы, активность, цель, любимые и нелюбимые ингредиенты, аллергии, ограничения. Возраст в прототипе — от 18 лет.

Пример функции персонализации: дневной ориентир 2200 ккал, съедено 1600, осталось 600. Если пользователь любит курицу и пасту, исключает рыбу и отмечает аллергию на арахис, приложение сначала отфильтрует противопоказанные по разметке блюда, затем поднимет выше пасту с курицей. При 165 ккал на 100 г предложенная порция 360 г содержит 594 ккал. Блюдо попадёт в дневник только после подтверждения пользователя.

## Распределение команды — 5 человек

### 1. Team Leader + Android-навигация

Создаёт репозиторий, собирает приложение, распределяет задачи и проверяет слияния. Отвечает за главный экран, навигацию между экранами и интеграцию общего кода. Первым делом разбивает `MainActivity` на отдельные экраны, чтобы участники не редактировали один файл одновременно.

Результат: приложение открывается, проходит основной сценарий и собирается у всей команды.

### 2. Android Developer — профиль и дневник

Делает анкету, выбор целей, экран добавления еды, список приёмов пищи, редактирование порций и состояния пустого дневника. Подключает готовые методы хранения и расчётов. Сохраняет черновики при повороте экрана.

Результат: пользователь может создать профиль и вести дневник без потери сохранённых записей.

### 3. Database Developer — локальные данные

Отвечает за SQLite, каталог продуктов и блюд, запросы по датам и историю веса. Переносит учебный каталог из кода в таблицы, добавляет состав и таблицы связей с аллергенами. Готовит миграции и данные для демонстрации. Серверную часть делать не требуется.

Результат: данные сохраняются после перезапуска, старые записи не меняются после редактирования каталога.

### 4. Nutrition Logic Developer

Отвечает за `NutritionCalculator`, `RecommendationEngine`, коэффициенты активности и цели, подбор порции, приоритет предпочтений и тесты. Обрабатывает отрицательный остаток и отсутствие подходящих блюд. Не снимает ограничения ради выдачи рекомендации.

Результат: расчёты воспроизводимы, алгоритм можно объяснить на защите, запрещённые по разметке блюда исключаются.

### 5. UI/UX + QA + презентация

Проектирует внешний вид экранов, палитру, карточки, поля и пустые состояния. Может помогать с XML-разметкой. Проверяет формы, навигацию, различные размеры экрана, сохранение, графики. Готовит документацию, слайды и демонстрацию.

Результат: единый внешний вид, список пройденных проверок и понятная защита.

Все участники работают над одним Android-приложением. Дизайн, база и расчёты делаются параллельно после согласования форматов данных; не нужно ждать завершения всей работы предыдущего участника.

## Минимум к защите

Создание локального профиля → расчёт нормы → добавление блюда → подсчёт съеденного → рекомендация → запись веса → просмотр истории. Все сохранённые данные должны переживать перезапуск приложения.

В MVP нет обязательной онлайн-регистрации. Если она входит в критерии учителя, вынесите её в отдельную задачу и добавьте время на облачный сервис авторизации, восстановление доступа и синхронизацию. Нельзя выдавать простую форму имени за систему аккаунтов.

Дополнения после стабильного MVP: план питания на день, пользовательские продукты, поиск в каталоге, вода, напоминания, сканер штрихкода. AI, распознавание еды по фотографии и недельный план — отдельные расширения, а не обещания первой версии.

## Внешний вид

Фон светлый `#F3F7F4`, основной зелёный `#16866A`, текст тёмный `#19362D`. Крупный показатель «съедено / норма», ниже БЖУ, заметная кнопка добавления еды. У каждого поля есть подпись и единицы измерения. Ошибки показываются обычным языком. Превышение калорий отображается нейтрально, без оценки пользователя.

## Защита за 5–7 минут

1. Объяснить проблему: вести питание неудобно, общие советы не учитывают предпочтения.
2. Показать стек и роли команды.
3. Создать профиль вымышленного взрослого: 25 лет, мужчина, 180 см, 80 кг, поддержание, низкая активность. Ориентир — 2166 ккал.
4. Добавить 200 г пасты с курицей: 330 ккал, 24 г белка, 10 г жиров, 36 г углеводов.
5. Отметить аллергию на арахис и показать, что йогурт с арахисом не предлагается. Отметить рыбу нелюбимой.
6. Показать рекомендации и объяснить: фильтрация → порция → предпочтения → три варианта.
7. Показать историю веса, закрыть и снова открыть приложение: данные остались.
8. Назвать ограничения учебного каталога и следующие улучшения.

Для красивого графика собирайте записи несколько дней. Ввод старых измерений — задача следующего этапа; не нужно менять дату телефона перед защитой.

План слайдов: проблема; идея; экраны; архитектура и база; алгоритм; демонстрация и тесты; вклад участников и развитие.
